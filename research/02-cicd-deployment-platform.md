# CI/CD, Deployment & Platform Engineering — research slice (as of 2026-10-18)

Method note: ~40 WebSearch calls (extended) until the shared search budget was exhausted, then ~90 WebFetch calls against primary sources (vendor pricing/docs pages, GitHub release pages, CNCF project pages, EC/SLSA/OTel specs). Vendor claims are labeled as such. Items I could not reach a primary source for are marked UNVERIFIED.

## 0. Headline findings

- GitHub Actions is simultaneously the market leader (47% org adoption, JetBrains 2026, n=598; up from 41%), the least reliable major GitHub service (57 outages May-2025→Apr-2026, 16 major), and the most attacked CI surface (tj-actions 2025; trivy-action, actions-cool tag hijack, GhostAction, Shai-Hulud cache poisoning in 2026). GitHub tried to monetize the control plane itself ($0.002/min for self-hosted runners, announced 2025-12-15, retracted within a week).
- A new "CI compute" layer (Blacksmith $45M B at $550M; Namespace $42M B, 8x revenue; Depot $10M A; RWX $12M A — all 2026) is eating the runner business from GitHub and is now building its own control planes (Depot CI executes Actions syntax without GitHub). Their shared thesis: coding agents multiply CI volume (Depot cites 25x in 6 months at one customer).
- Deploy side is fragmenting: Heroku frozen (sustaining mode, Feb 2026), AWS App Runner closed to new customers (2026-04-30), while self-hosted PaaS (Coolify 63k stars, Dokploy 38k) and Kamal (Rails 8 default) boom. Nobody offers forge + CI + registry + environments + progressive delivery + secrets as one product with one identity/policy model.
- Regulatory tailwind: EU CRA reporting duties live since 2026-09-11; SBOM/full obligations 2027-12-11.

- **The retracted self-hosted fee**: 2025-12-15 GitHub announced price cuts plus a $0.002/min "Actions cloud platform charge" for self-hosted runners in private repos from 2026-03-01; postponed ~1 week later after backlash ("missed the mark"). The $0.002 platform charge is now baked into hosted prices. GitHub cited >70M jobs/day (vs 23M early 2024) (https://samexpert.com/github-actions-pricing-backlash-2026/).
- **Limits** (https://docs.github.com/en/actions/reference/limits): job 6h hosted / 5 days self-hosted; workflow 35 days; matrix 256 jobs; concurrency Free 20 / Pro 40 / Team 60 / Enterprise 500 (macOS 5 on all but Enterprise 50); cache 10 GB/repo default (org policy page mentions a 10,000 GB ceiling), retention 7 days default/365 max; artifact storage 500 MB Free, 2 GB Team, 50 GB Enterprise; included minutes 2,000 / 3,000 / 50,000; GITHUB_TOKEN API 1,000 req/h/repo.
- **Reliability**: May-2025→Apr-2026: 257 GitHub incidents, 48 major, 112h18m major downtime, MTTR 6h07m; Actions 57 outages (most of any service, 3x core Git), capacity the root cause in 83/257; only 12.5% of traffic on Azure as of Mar-2026 (https://blog.incidenthub.cloud/github-reliability-outage-history-2025-2026). July 2026 availability report: Jul 9 hosted-runner provisioning outage 9h18m; Jul 19-20 expired SSL cert in the min-runner-version enforcer delayed 79% of larger-runner jobs >5 min; Jul 25 Redis region failure (https://github.blog/news-insights/company-news/github-availability-report-july-2026/). Aug 6 2026 ~10h Actions outage; Oct 5 2026 14.3% of workflow runs / 26.5% of hosted jobs not started within 5 min (githubstatus). Depot computes ~97.5% Actions uptime over a 3-month window (~54h down) (https://depot.dev/blog/github-actions-without-github).
- **Supply-chain incidents**: tj-actions/changed-files (CVE-2025-30066), 2025-03-14/15, used by 23k+ repos; chain started by exploiting spotbugs' workflow (Nov 2024) → reviewdog PAT → tj-actions bot PAT; payload dumped runner memory to logs (https://unit42.paloaltonetworks.com/github-actions-supply-chain-attack/, https://www.wiz.io/blog/github-action-tj-actions-changed-files-supply-chain-attack-cve-2025-30066). 2026: trivy-action compromise (TeamPCP, Mar 2026); actions-cool/issues-helper + maintain-one-comment (May 2026) — every tag moved to an "imposter commit" living only in a fork, payload reads Runner.Worker memory and exfiltrates via HTTPS, linked to Mini Shai-Hulud/@antv npm (https://thehackernews.com/2026/05/github-actions-supply-chain-attack.html); the repos were re-enabled 2026-09-16 without cleanup and re-executed the payload (https://thehackernews.com/2026/09/compromised-github-actions-came-back.html). GhostAction wave 2 (Aug 31–Sep 30 2026): 373 maintainer accounts, 772 repos, 2,577 secrets targeted, 26 confirmed exfiltrated; wave 1 (2025) 3,325 secrets/817 repos; technique = malicious `security-audit.yml` pushed by compromised maintainers, harvesting cloud keys and Anthropic/OpenAI API keys (https://www.decryptiondigest.com/blog/ghostaction-github-actions-supply-chain-2026). Shai-Hulud TanStack wave (May 2026) poisoned the Actions cache via a Pwn Request then waited for the legit release workflow; the 172 malicious packages carried **valid SLSA Build L3 provenance** (https://venturebeat.com/security/shai-hulud-worm-172-npm-pypi-packages-valid-provenance-ci-cd-audit).
- **Platform responses**: org policy "Require actions to be pinned to a full-length commit SHA" (reusable workflows exempt; lockfile-pinned actions satisfy it), allow-lists capped at 1,000 entries (https://docs.github.com/en/organizations/managing-organization-settings/disabling-or-limiting-github-actions-for-your-organization); immutable releases lock tag+assets and auto-emit a release attestation, blocking "repository resurrection" tag reuse (https://docs.github.com/en/code-security/supply-chain-security/understanding-your-software-supply-chain/immutable-releases); npm: OIDC trusted publishing with auto-provenance, classic tokens deprecated, 7-day granular tokens, staged publishing, npm 12 disables install scripts by default, new trusted-publisher configs must first-publish within 2 days (Oct 2026) (https://thehackernews.com/2026/10/github-tightens-npm-publishing-after.html).
- **Self-hosted/ARC pain**: runners < v2.329.0 blocked from 2026-03-16; runners >30 days stale stop receiving jobs; ARC "Waiting for a runner" with no diagnostics; spot interruptions (5% rate on 20k min/mo ≈ +1,000 min re-runs); CVE patching is yours; self-hosted runners on public repos = RCE (https://cicdpipelinecost.com/self-hosted-runners, https://aws.plainenglish.io/self-hosted-github-runners-on-eks-13-gotchas-nobody-warns-you-about-d19817d1af2f). JetBrains 2026: teams switching CI cite scaling cost 24%, maintenance 23%, complex configuration 21% (https://www.jetbrains.com/pages/state-of-cicd2026/).

No reliable survey of CI as % of engineering budget was found — UNVERIFIED.

GitHub's attempted $0.002/min self-hosted fee signals the control plane is where the margin pressure is (70M jobs/day).

## 7. "End-to-end in one place" — who is trying, why they fall short

- **GitLab**: closest to a single application, but the useful bits are tiered (approvals Premium, DORA Ultimate, AI by $1 credits), Actions-era ecosystem gravity is with GitHub, YAML-only, and its own DORA admits blind spots for pull-based deploys.
- **Harness**: 10+ modules sold separately by quote; IDP/flags/cost Enterprise-only; OSS Gitness stops at registry (no environments/rollouts).
- **Depot / Blacksmith / Namespace / RWX**: own the execution layer and are building control planes, but none own source, review, environments or rollout; Depot explicitly designs adapters so any forge (incl. Cursor's Origin) can plug in.
- **Vercel/Netlify/Railway/Render/Fly + GitHub**: superb deploy UX (Vercel Rolling Releases is the best built-in canary in the market) but frontend/one-stack-centric, no CI control, previews and rollouts gated per plan (Rolling Releases: 1 project on Pro).
- **Coolify/Dokploy/Kamal**: deploy-only, depend on external Git + CI; no attestations, no environments model, no policy.
- **Forgejo/Gitea/OneDev/Harness OSS**: forge + CI + registry, but zero deploy/environment/rollout semantics; OneDev (MIT, 15.3k stars) is the only forge with GUI-first non-YAML pipelines (https://github.com/theonedev/onedev).
- **Garnix**: genuinely code→CI→cache→PR-deploy→server-deploy in one, but Nix-only.
- **Non-YAML pipeline languages**: Dagger (typed SDKs + modules), RWX (DAG tasks), Bazel/Starlark, Nix, OneDev GUI; CUE has no major CI product behind it (commercial adoption UNVERIFIED). Nobody has unified a typed pipeline language with environments, release trains and rollout policy.

## Design implications for a forge with built-in end-to-end deployment

1. **Own the control plane, make execution pluggable.** GitHub Actions' 57 outages/yr and the attempted self-hosted fee show the dispatcher is both the weak point and the monetization point. Dispatch, secrets issuance, caching and status must be yours; runners (yours, BYO, Blacksmith/Namespace/Depot-style partners) are interchangeable. Never charge for BYO runners — that is exactly what GitHub retracted.
2. **Ship an Actions-syntax compatibility layer as the on-ramp, not the native model.** Forgejo, Gitea and Depot CI prove migration demand; Depot shows what it takes (action mirroring, cache/artifact endpoint redirection, API adapters). The native model should be a typed DAG of content-addressed tasks (Dagger/RWX/Bazel ideas), edited as code or GUI (OneDev), compiled from YAML when imported.
3. **Make "imposter commits" impossible.** Resolve every action/module reference to a SHA at plan time, refuse refs that are not ancestors in the referenced repo's history, lock tags on release (GitHub immutable releases), vendor third-party actions into your registry, and default to SHA-pin policy. Every 2025-26 Actions incident was defeated only by SHA pinning.
4. **Treat caches as a trust boundary.** The TanStack wave poisoned the Actions cache from a fork PR. Caches must be content-addressed, write-scoped by ref/trust level (RWX "branch-locked vaults"), and carry provenance of what produced them.
5. **Secrets never sit as plaintext env vars in a shared runner process.** GhostAction and actions-cool both scraped Runner.Worker memory. Use a secrets enclave + per-job OIDC identity that exchanges for short-lived cloud creds, scoped to environment and ref; deny secrets to fork PRs by default; enforce egress allow-lists with alerts (exfil in 2026 went to raw IPs and look-alike domains).
6. **Bill by work, not minutes, using content-addressed execution.** Dagger charges 1/5 for repeat work; RE API's CAS/action cache is the proven mechanism. This is the only cost story that survives agent-driven 25x CI volume, and it differentiates from every per-minute runner vendor.
7. **Ephemeral microVM per job on owned bare metal, per-second billing, ARM + macOS from day one.** All three funded runner vendors converged here; macOS is a 6-12x price multiplier at GitLab/Namespace and a 5-concurrency cap at GitHub — a wedge for mobile teams.
8. **Agent-native validation before commit.** Expose the pipeline API so agents run named steps on uncommitted diffs (`rwx run`, Depot API), reuse those results to skip post-commit runs, and do automatic test selection from VCS data. Measure "mean time to trust", not just pipeline latency.
9. **Built-in OCI registry with referrers and attestations, free intra-platform transfer.** ghcr.io is free for now; Gitea proves 23 formats is table stakes; Depot/Namespace charge $0.20/GB-mo for storage. Store build caches, Tofu modules/providers (OpenTofu OCI support), Helm charts and SBOMs in the same CAS.
10. **Be the Source Control System that SLSA v1.2 describes.** Issue source VSAs per revision, enforce continuity (no force-push, protected tags), record two-party review (Source L4), and generate Build L3 provenance for every artifact. Then enforce *policy* at deploy time — provenance alone did not stop Shai-Hulud.
11. **CRA compliance as a product feature.** Auto-generated SBOMs per release (CycloneDX/SPDX), support-period metadata, a vulnerability-handling workflow with the 24h/72h/14d ENISA clocks, and release attestations map directly to obligations landing 2026-09-11 and 2027-12-11. Sell this to EU vendors who otherwise buy Cloudsmith/Finite State.
12. **Environments are first-class objects, and every deploy creates a record regardless of push vs pull.** GitLab's DORA is Ultimate-only and blind to agent-based deploys; GitHub's approvals allow any 1 of ≤6 reviewers. Offer N-of-M approvals, wait timers, branch/tag rules, custom rules via apps, environment-scoped secrets, and a deployment ledger that feeds DORA (including Rework Rate and Failed Deployment Recovery Time).
13. **Progressive delivery for any container, built in.** Copy Vercel Rolling Releases' shape (stages, sticky bucketing, metric comparison, instant rollback, API lifecycle) and Argo Rollouts' analysis (Prometheus/Datadog queries) but make it work for backends on VMs and K8s; add an OpenFeature-compatible flag service (Vercel/GitLab bundle flags; OpenFeature is CNCF Incubating, not graduated).
14. **Per-PR preview environments for any stack via Compose/Helm with TTL and sleep.** Coolify/Northflank/Okteto include them; Bunnyshell meters $0.007/min/env. Bundle a fair quota, meter beyond it; attach the preview URL and cost to the PR.
15. **Hide the GitOps controller, support both paths.** Embed an Argo-style reconciler (97% prod adoption, hydrator/rendered-manifest pattern) for K8s shops and a Kamal-style imperative SSH/Docker path for VMs and bare metal (Rails 8 default; Coolify/Dokploy's 100k combined stars show most SMB teams do not want K8s). Allow export to Argo/Flux to avoid lock-in fear.
16. **Native OpenTelemetry CI/CD spans and deployment-ID propagation.** Emit `cicd.pipeline.*` spans (RC conventions already implemented by Tekton), tag every deploy with an ID consumable by Datadog/Grafana, and compute DORA from forge data without Jira.
17. **Embed an MPL/MIT secrets manager (OpenBao-compatible API) and IaC with OpenTofu.** HashiCorp's BSL under IBM is a liability for an OSS forge; OpenBao gives namespaces, dynamic secrets and PQC for free; OpenTofu adds OCI-distributed modules and state encryption.
18. **Agent-context, not portal.** Backstage contributions are falling (−24% contributors YoY), Roadie is pivoting to "Enterprise Context", Port sells agents; JetBrains shows 28% of teams already use MCP to reach CI/CD. Expose the forge's graph (services, envs, deploys, owners, SBOMs) as an MCP server with policy, rather than building a Backstage clone.
19. **Cost attribution per PR/env/deploy built in.** Qovery charges $3,588/cluster/yr for observability, Bunnyshell gates cost reporting at 20 users, Harness puts cloud cost in Enterprise — include CI minutes, preview-env minutes and runtime cost on the PR and on the environment page by default.
20. **Business model: open-core forge, charge for compute/cache/env-minutes, never for the control plane you want adopted.** Earthly died trying to charge for an OSS build tool whose value was fully available for free; Blacksmith/Namespace/Depot thrive selling scarce compute (macOS, bare metal) and cache storage; Coolify grows on donations + cloud. GitHub's retracted fee defines the ceiling on control-plane pricing.
21. **Offer a hermetic/Nix path.** Garnix is the only vendor with CI+cache+PR-deploy+server-deploy in one product; supporting Nix flakes as a first-class build input gives reproducible builds for the teams that need SLSA L3 and CRA evidence without inventing a new build system.
22. **Plan for a new forge entrant: Cursor's Origin.** "A git forge for the agentic era" (early beta on paid plans) with Depot CI as launch partner indicates the AI-IDE vendors will bundle forge + agents + CI; differentiate on deployment, environments, policy and open source, which Origin does not list.
