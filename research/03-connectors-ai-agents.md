## 1. Integration surfaces of incumbents

**GitHub: three surfaces, one winner.** GitHub Apps (own identity, installation tokens scoped to chosen repos + fine-grained permissions, short-lived, receive `installation` webhooks, exempt from org OAuth-app policy) have displaced OAuth Apps (act as the user; `repo` scope = full contents access just to read issues) (https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/differences-between-github-apps-and-oauth-apps). Webhooks are the third surface: repo/org/app-level, HMAC-signed, but with **no automatic redelivery** and a 10-second response deadline (30 s on GHES docs) (https://docs.github.com/en/webhooks/using-webhooks/handling-failed-webhook-deliveries). Known pain: app permission sets are all-or-nothing — e.g. the Claude GitHub App requests 13 permissions (Actions RW, Contents RW, Repository hooks RW, Workflows RW…) and "GitHub doesn't let you accept a subset" (https://code.claude.com/docs/en/github-actions).

**GitHub Marketplace.** Lists both Apps and Actions; paid listings require org-owned apps + publisher verification + the Marketplace Developer Agreement (https://docs.github.com/en/apps/github-marketplace/github-marketplace-overview/about-github-marketplace-for-apps). Revenue share: developers keep **95%**, GitHub takes 5% (changed from 75/25 on 2021-02-04) (https://www.infoworld.com/article/2262388/github-increases-developers-cut-of-github-marketplace-sales.html). App counts conflict: a third-party aggregator lists ~1,088 apps from 822 vendors; "20,000+" figures include Actions — UNVERIFIED. Marketplace revenue is not disclosed.

**GitLab.** Integrations are first-party, built into the product rather than a marketplace: Jira issues + "GitLab for Jira Cloud app", "GitLab for Slack app" (legacy Slack notifications deprecated), Datadog pipeline tracing, etc., exposed via a project-integrations REST API (https://archives.docs.gitlab.com/15.7/ee/api/integrations.html). GitLab's AI surface is now its MCP server (see §2).

**Bitbucket Cloud.** Atlassian is retiring Connect for Forge (serverless apps hosted on Atlassian infra): no new Connect apps/installs from **2026-02-02**, Connect updates stop **2026-03-31**, Bitbucket-specific end of support **2027-01-31**; paid Forge apps on Bitbucket "later, date TBC" (https://community.developer.atlassian.com/t/bitbucket-cloud-announcing-connect-end-of-support-timeline-and-next-steps/98760, https://www.atlassian.com/blog/development/announcing-connect-end-of-support-timeline-and-next-steps). Lesson: incumbents are moving to hosted, sandboxed app runtimes with platform-controlled auth.

**Categories that matter (evidence of what vendors wire first).** Hookdeck's own alerting integrations — Slack, Discord, Teams, PagerDuty, Better Stack, incident.io, Sentry; metrics export to Datadog/New Relic/Prometheus; SSO/SAML/SCIM at the $499 tier (https://hookdeck.com/pricing) — are a good proxy for the minimum enterprise connector set. Security scanners integrate through **SARIF**: `github/codeql-action/upload-sarif@v4` or the code-scanning REST API, `security-events: write`, one SARIF per tool/category, `partialFingerprints` for dedup (https://docs.github.com/en/code-security/code-scanning/integrating-with-code-scanning/uploading-a-sarif-file-to-github) — Semgrep/Snyk/SonarQube/Trivy all emit SARIF, so a forge gets the whole scanner category by implementing one ingest endpoint + PR annotation UI. Issue trackers are converging on an **agent-aware** model: Linear's Agent Interaction SDK gives agents their own identity/token (`actor=app`), `app:assignable` / `app:mentionable` scopes, team-scoped installs, and webhook-driven "agent sessions" with states (waiting / working / completed / errored) (https://linear.app/now/our-approach-to-building-the-agent-interaction-sdk, https://linear.app/docs/agents-in-linear). Audit/identity connectors (Okta, Entra, Splunk, Datadog, S3) are in §6.

## 2. MCP as the universal connector standard

**Status.** Anthropic donated MCP to the Linux Foundation's **Agentic AI Foundation (AAIF)** on 2025-12-09, co-founded with Block (goose) and OpenAI (AGENTS.md); Google, Microsoft, AWS, Cloudflare, Bloomberg backing; "more than 10,000 active public MCP servers" (https://anthropic.com/news/donating-the-model-context-protocol-and-establishing-of-the-agentic-ai-foundation, https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation). Secondary trackers: ~97M monthly SDK downloads by March 2026; official registry ~9,652 servers in May 2026 and a claimed 43,298 by 2026-10-14 (https://gravity.fast/data/mcp-adoption-statistics/) — the latter UNVERIFIED. Official MCP Registry previewed 2025-09-08 (registry.modelcontextprotocol.io; sub-registries, denylist moderation) (https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/); GitHub's own registry at github.com/mcp lists **490 servers** (Microsoft, Stripe, Figma, Notion, Supabase…).

**Spec trajectory (important for anyone building a server now).** Revisions: 2025-03-26, 2025-06-18, 2025-11-25 (Tasks experimental, Client ID Metadata Documents, client-credentials, URL-mode elicitation, extensions framework), and **2026-07-28 (current)**, which makes MCP *stateless*: no `Mcp-Session-Id`, no `initialize` handshake, new `server/discover`, `subscriptions/listen`, Tasks moved to an extension, a multi-round-trip request pattern replacing server-initiated sampling/elicitation, deterministic `tools/list` ordering + `ttlMs`/`cacheScope` for prompt-cache hits, OTel trace-context in `_meta`, Roots/Sampling/Logging and Dynamic Client Registration deprecated with a 12-month deprecation policy (https://modelcontextprotocol.io/specification/2026-07-28/changelog).

**Auth.** OAuth 2.1 with: mandatory RFC 9728 Protected Resource Metadata on servers, RFC 8414/OIDC discovery, PKCE S256 required, RFC 8707 `resource` indicators required, audience validation required, **token passthrough forbidden**, step-up scope challenges via 403 `insufficient_scope`, CIMD (HTTPS URL as client_id) preferred over DCR (https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization). Adoption gap: one March 2026 survey found only ~8.5% of surveyed MCP servers use OAuth and 53% rely on long-lived static secrets (https://nimblebrain.ai/blog/state-of-mcp-security-2026/ — secondary).

**Forge MCP servers today.** GitHub: remote server at `api.githubcopilot.com/mcp/`, GA 2025-09-04 with OAuth 2.1+PKCE, 22 toolsets (context, repos, issues, pull_requests, actions, code_security, dependabot, discussions, projects, secret_protection…), default set = context/repos/issues/pull_requests/users, `--read-only` flag, MIT, 33.7k stars; GHES only via local server (https://github.com/github/github-mcp-server, https://github.blog/changelog/2025-09-04-remote-github-mcp-server-is-now-generally-available/). GitLab: MCP server GA in 19.5 (2026-10-15) on Free/Premium/Ultimate incl. Self-Managed/Dedicated; tools include `semantic_search`, consolidated `get_merge_request`, pipeline/artifact tools, and Duo Agent Platform session tools (`start_duo_session`, `send_duo_session_input` for approvals); runs under the user's permissions, OAuth tokens limited to `mcp`+`ai_workflows` scopes, composite identity takes the most restrictive role; rate limits 60/min Free, 600/min paid (https://about.gitlab.com/blog/mcp-server-ga/, https://docs.gitlab.com/user/model_context_protocol/mcp_server_tools/). Gitea ships an official server (gitea/gitea-mcp v1.9.0, 2026-10-16: stdio + stateless HTTP, OAuth 2.1 PKCE, read-only mode, mTLS) (https://gitea.com/gitea/gitea-mcp); Forgejo/Codeberg only have community servers (e.g. one exposing 457 tools) — a gap.

**Security.** Invariant Labs (2025-05-26) showed a "toxic agent flow": a prompt injection in a public issue made an agent using the GitHub MCP server read private repos and leak salary data via a public PR; demoed with Claude 4 Opus; not a code bug but an architecture problem (private data + untrusted content + exfil channel). Mitigations: per-session single-repo policies, runtime scanning (https://invariantlabs.ai/blog/mcp-github-vulnerability). Tool poisoning (malicious instructions in tool descriptions) and rug pulls (definitions change after approval) are the other headline threats; defenses are schema pinning/diffing and signed tool definitions (ETDI paper, https://arxiv.org/pdf/2506.01333). GitHub Next's **Agentic Workflows (gh-aw, tech preview 2026-02-13)** is the cleanest reference architecture: agent jobs run read-only with a read-only GitHub MCP, and every write goes through a "safe outputs" MCP gateway that validates JSON-schema tool calls, enforces per-type limits, and applies them in a separate job with scoped permissions (https://github.github.com/gh-aw/reference/safe-outputs/, https://github.blog/changelog/2026-02-13-github-agentic-workflows-are-now-in-technical-preview/).

**Adjacent conventions.** A2A: 150+ supporting orgs (LF, 2026-04-09), v1.0 March 2026, joined AAIF Aug 2026, but production use is far smaller than MCP's; one informal probe of 50 A2A endpoints found none returning a correct task response (single source) (https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year, https://credal.ai/blog/what-happened-to-a2a-protocol). **AGENTS.md**: 60,000+ repos, AAIF-stewarded, nearest-file-wins semantics, read by Codex, Jules, Gemini CLI, Cursor, Copilot coding agent, Devin, Windsurf, Amp, Factory, Augment, Zed, Warp, etc. (https://agents.md/). **llms.txt**: adoption 5–28% depending on sample; Ahrefs' 137K-site study found 97% of files get zero crawler traffic and Google says it doesn't use it (https://ahrefs.com/blog/llmstxt-study/) — low priority for a forge.

## 7. Webhook / event architecture

GitHub's model is the cautionary tale: no automatic retries, 10-s timeout, manual or scripted redelivery (official sample runs every 6 h), dedupe on `X-GitHub-Delivery`, ~3-day redelivery window (UNVERIFIED) (https://docs.github.com/en/webhooks/using-webhooks/best-practices-for-using-webhooks). **Standard Webhooks** (TSC: Zapier, Twilio, Lob, Mux, ngrok, Supabase, Svix, Kong; adopters incl. OpenAI, Anthropic, Google Gemini, MCP, PagerDuty, Brex): `webhook-id` / `webhook-timestamp` / `webhook-signature`, HMAC-SHA256 (`v1`) or ed25519 (`v1a`), multiple signatures for rotation, exponential backoff + jitter over ~75 h, honor `410 Gone` and `retry-after`, 15–30 s timeout, payloads <~20 KB, thin-vs-full payload guidance (https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md). **CloudEvents** 1.0.2 is CNCF-graduated (2024-01-25) with 36 adopters (EventBridge, Event Grid, Eventarc, Knative, Argo Events, Tekton, Debezium, Harbor); HTTP/WebSocket bindings, JSON/Protobuf (https://cloudevents.io/). Vendors: Svix (MIT Rust open-source server; 50K msgs free, Basic $20, Pro $490, $0.0001/msg; 7/30/90-day retention; Enterprise adds polling/FIFO endpoints, OTel streaming, on-prem) and Hookdeck (inbound gateway; free 10K events, Team $39, Growth $499 with 99.999% SLA + SSO/SCIM; $3 per 100K overage; Outpost open-source outbound) (https://www.svix.com/pricing/, https://hookdeck.com/pricing). ## Design implications: how a new forge should do connectors and AI-agent-native workflows

1. **Make the "App" the only third-party identity, with capability-scoped, short-lived installation tokens and partial-permission acceptance.** GitHub Apps won on fine-grained scopes; the remaining pain is all-or-nothing permission sets (13-permission Claude app). Let installers accept a subset and let apps declare per-feature permission bundles.
2. **Ship a native, remote MCP server as a first-class API surface — stateless per the 2026-07-28 spec, OAuth 2.1 with RFC 9728/8707, PKCE, CIMD, and audience-bound tokens; publish to the official registry.** GitHub (22 toolsets, GA Sept 2025), GitLab (GA Oct 2026) and Gitea (v1.9.0) all have one; Forgejo/Codeberg don't. Default to a small read-mostly toolset, `--read-only` mode, deterministic tool ordering with `ttlMs` for prompt caching.
3. **Enforce the gh-aw "safe outputs" split in the platform itself:** agent sessions get read-only tokens; every write (comment, push, PR, label) passes through a schema-validated, rate-limited, policy-checked gateway that executes with separately scoped credentials. This directly neutralizes the Invariant Labs toxic-flow class.
4. **Treat issue/PR text as untrusted input for agents:** per-session single-repo token policies (Invariant's recommendation; Copilot's default), content provenance tags on comments (external contributor vs member vs bot), and a "quarantine" mode where agents can read untrusted content only through sanitized/summarized views.
5. **Pin and sign tool definitions and plugins.** Rug pulls and tool poisoning are the top MCP threats; tj-actions showed mutable tags leak secrets across 23K repos. Require SHA/digest pinning for actions and plugins, show schema diffs on update, and re-prompt consent when a tool's description changes.
6. **Give agents first-class identity: delegate ≠ assign.** Copy Linear: an issue keeps a human assignee and a *delegated* agent; agents are labelled, have their own token/permissions, team-scoped installs, `assignable`/`mentionable` capabilities, and visible session state (waiting/working/done/errored). "An agent cannot be held accountable."
7. **Record provenance structurally, not in commit trailers.** Trailers are contested (`Co-authored-by` vs `Assisted-by`), stripped by squash merges, and Cursor emits none. Store per-commit/per-hunk authorship metadata (human, agent, model, session ID, prompt hash) in the forge database and signed notes, expose it in the PR UI, filters, and audit log, and let repos require it.
8. **Build loop-prevention and actor checks into events.** Claude's action refuses bot actors unless allow-listed and warns that agent replies trigger `issue_comment` automations; GitHub won't run CI on `GITHUB_TOKEN` pushes. Make "who triggered this, human or bot, with what write level" a first-class event attribute and let workflows gate on it.
9. **Ship sandboxed, credential-less runners with a credential proxy.** Claude's cloud sessions keep git credentials out of the VM and attach scoped creds via a proxy; Codex uses per-environment egress allowlists and network secrets. Offer this as forge infrastructure: ephemeral VMs, egress allowlists, OIDC-federated secrets, no long-lived tokens inside the sandbox.
10. **Make PR review APIs agent-grade:** structured review objects (findings with severity, file ranges, suggested fix, confidence), batch autofix, cluster duplicate findings, memory across PRs (all things Copilot review added by March 2026), plus policy knobs for whether bot approvals count toward branch protection (GitHub's Sept 2026 debate).
11. **Default to review-load controls.** Data: agent PRs are accepted less, need 1.62× more follow-up fixes, and reviewer engagement is the top merge predictor. Provide per-repo agent PR quotas, draft-by-default for agent PRs, required "rationale/validation/owner" fields, auto-close policies for non-members, and review-queue triage views ("agent inbox").
12. **Native stacked PRs + merge queue + review tooling, not a marketplace add-on.** GitHub went native July 2026; Cursor bought Graphite; Mergify/Aviator charge $20–21/seat. Bundle stacking, queue, and an open AI reviewer slot (bring-your-own model) in core.
13. **Events as CloudEvents over Standard Webhooks, from a transactional outbox, with replay.** Implement `webhook-id/timestamp/signature`, HMAC + ed25519, key rotation via multiple signatures, 72-h backoff with jitter, `410 Gone` handling, per-endpoint queues, replay by ID/time range, thin payloads with a full-payload opt-in — i.e. fix GitHub's no-retry/10-s model. Consider embedding the MIT Svix server rather than building from scratch.
14. **One ingest standard per category:** SARIF for scanners (upload API + PR annotations + dedup fingerprints), OTel for traces/metrics, SCIM 2.0 + SAML/OIDC for identity, CloudEvents/webhooks out, MCP in/out for agents. That covers Snyk/Semgrep/SonarQube/Trivy, Datadog/Grafana/Sentry, Okta/Entra/Google, and every AI client with one implementation each.
15. **Enterprise baseline before the first paid deal:** SAML + SCIM (Entra, Okta, PingFederate tested), audit-log streaming to Splunk/Datadog/S3/Event Hubs with at-least-once semantics and health checks, IP allow lists that cover tokens and SSH (not just SSO), fine-grained tokens with admin approval, SSH CAs with <366-day certs, data-residency regions, and signed-commit verification that actually honors SSH certificates and Sigstore/gitsign (GitHub shows them "Unverified" — an easy win).
16. **Built-in code intelligence: Zoekt-class text search + SCIP precise navigation + optional embedding search.** GitHub's Blackbird numbers show the index is ~¼ of raw size with blob-level dedup; Sourcegraph's exit from open source leaves the open slot. Expose search/navigation as MCP tools (GitLab already ships `semantic_search`).
17. **Plugin runtime = WASM Components (WASI 0.3) with capability-based imports and a hosted serverless tier.** Atlassian's forced Connect→Forge migration and Backstage's 250+ plugin ecosystem show the demand; Extism today for breadth of SDKs, Component Model for the long term. Keep GitHub-Actions YAML compatibility (as Forgejo does, with documented deviations) so the 20K+ existing actions port.
18. **Marketplace economics ≥ GitHub's 95/5, with metered agent-usage billing hooks.** AI reviewers are converging on per-seat + per-review/credit models (CodeRabbit $0.25/file, Greptile $1/review, Copilot 13 premium requests/review); give vendors a usage-metering API and let customers set per-repo budgets.
19. **Publish AGENTS.md support and render it; skip llms.txt.** 60K+ repos and every major agent read AGENTS.md; treat it (plus nested files) as structured repo context served via MCP resources. llms.txt has <3% crawler uptake.
20. **Design against lock-in that the incumbents enforce:** Claude cloud sessions can't push to GitLab/Bitbucket; Copilot agent works only on GitHub; Ellipsis/Mergify are GitHub-only. A forge that exposes the same PR/review/check/event semantics via a GitHub-compatible REST surface plus MCP lets third-party agents and reviewers onboard without new integrations — the fastest route to "all the connectors."
