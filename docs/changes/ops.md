# Operations slice: Postgres profile, backups and restore, ops commands, packaging

Branch `slice/ops` (built in the delivery session's worktree). Owns `internal/ledger/ledger.go`, `internal/ledger/pg/` (new), `internal/ledger/dump.go` (new), `deploy/`, `scripts/release.sh`, `scripts/test-postgres.sh`, `cmd/ore/`. No new migration; the existing migration files are untouched (the dialect rewrite makes them run on Postgres).

## What landed

**Two SQL targets, one set of statements (ADR 0006).** `ledger.Open` takes a SQLite path (bare, `sqlite:path`, `sqlite:///abs/path`) or a Postgres URL (`postgres://user:pass@host:5432/db?sslmode=...`), from `--db` / `ORE_DB_URL`; without either the ledger is `<data>/ore.db` as before. The only new dependency is `github.com/jackc/pgx/v5` (stdlib driver). Every statement in the repository stays in SQLite's dialect with `?` placeholders; `internal/ledger/pg` rewrites it on the way out:

| SQLite | Postgres | where |
|---|---|---|
| `?` placeholders | `$1..$n` (string literals, quoted identifiers and comments are skipped) | every `DB.Query/QueryRow/Exec` and every `Tx.ExecContext/QueryContext/QueryRowContext`; `Tx` now shadows the embedded `*sql.Tx` methods, so existing callers need no change |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | migrations |
| `INTEGER` | `BIGINT` (SQLite integers are 64-bit; GitHub ids and byte sizes exceed int4, which the Postgres suite caught) | migrations |
| `BLOB` | `BYTEA` | migrations |
| `UNIQUE constraint failed` in the error text | SQLSTATE 23505 is wrapped so the message carries `UNIQUE constraint failed` too; `ledger.IsUniqueViolation(err)` is the proper check | `DB.Exec/Query`, `Tx.*` |

Audit of the repository's queries: `ON CONFLICT ... DO UPDATE SET x = excluded.x` (review, delivery, github stores) is valid on both; `COALESCE`, `CASE`, `LIKE`, `IN (...)`, `ORDER BY ... LIMIT ?`, `COUNT(1)`, `MAX()` are valid on both; TEXT timestamps compare lexically on both; no `datetime()`, `strftime`, `GROUP_CONCAT`, `IFNULL`, `INSERT OR REPLACE`, `RETURNING` or JSON functions are used anywhere. Three places detected duplicates by searching the error text for `UNIQUE` (identity, delivery, github); the wrapper keeps them working on Postgres. Column names that are keywords elsewhere (`at`, `time`, `type`, `comment`, `role`, `policy`) are non-reserved in Postgres and needed no quoting. Migrations run as one multi-statement `Exec` per file on both drivers.

**Migrations.** `Migrate` serializes migrators: a Postgres advisory lock for the whole run, and on SQLite immediate transactions (`_txlock=immediate`) with a re-check of `schema_migrations` inside each one and retries on `SQLITE_BUSY`, so a second `ore migrate` waits or finds the work done. `ore migrate status` opens without migrating (`ledger.OpenWith(..., Options{NoMigrate: true})`) and lists each embedded file with its applied time; `ore migrate apply` applies and lists. The SQLite DSN now sets `busy_timeout` before `journal_mode(WAL)` so concurrent openers do not fail on the WAL switch.

**Test database hook.** When `ORE_TEST_DB_URL` is set, every `ledger.Open` of a SQLite target in the test suite is redirected to that Postgres server in a fresh schema (`search_path`), dropped on `Close`. No test changed. `scripts/test-postgres.sh` starts `postgres:16-alpine` on a free port, exports the URL, runs `go test ./...` and stops the container.

**Backups.** `ore backup --to DIR` writes: `ore.db` (a `VACUUM INTO` copy; SQLite ledgers), `ledger.jsonl` (the portable dump, every dialect: a header line per table, one JSON line per row, cells tagged as `{"i"}`/`{"f"}`/`{"s"}`/`{"b"}`/`null`, tables in foreign-key order, read from one snapshot; this is the pg_dump equivalent through the server's own connection), `repos/<org>/<name>.bundle` (`git bundle create --all`; empty repositories are recorded as empty), `files/token`, `files/secrets.key`, `files/actions-refs.json` when present, and `manifest.json` with SHA-256 and size of every file, the dialect, the version and the repositories. `--to s3://bucket/prefix` stages locally and uploads with AWS Signature V4 (credentials from `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN`, region from `AWS_REGION`, `AWS_ENDPOINT_URL` for MinIO and friends, path-style), manifest last. A non-empty destination directory is refused. Scheduled backups: `ORE_BACKUP_TO` (or `--backup-to`) with `ORE_BACKUP_INTERVAL` (24h) and `ORE_BACKUP_KEEP` (7) write `<to>/<YYYYMMDDThhmmssZ>` and prune the oldest local ones; S3 prefixes are not pruned (use a bucket lifecycle rule).

**Restore.** `ore restore --from DIR [--data DIR] [--db URL]` verifies every checksum first, refuses a non-empty data directory, writes the sidecar files (mode 0600), restores the ledger (copies `ore.db` when the target is SQLite and the backup has it; otherwise opens the target, applies migrations and loads `ledger.jsonl` into the empty database, advancing identity sequences on Postgres; `ledger.ErrNotEmpty` if the database has rows), then recreates each repository from its bundle (`git clone --bare`, origin removed, HEAD set) or as an empty bare repository on the recorded default branch. A SQLite backup restores into Postgres and back, since the dump is dialect-neutral.

**Litestream.** `deploy/litestream.yml` and the `litestream` compose profile replicate `/data/ore.db` continuously to S3; repositories are not in SQLite and are covered by `ore backup`.

**Commands and configuration.** `ore config` prints the effective configuration (flags over `ORE_*` variables over defaults) as JSON with the token and the database password redacted. `ore doctor` checks git and `git http-backend`, docker (absent or dead: a warning that pipelines fall back to `--executor host`, never a failure), the data directory (created if missing, writable, token mode 0600), repositories, the database (connectivity, pending migrations, counts; failures carry the redacted target), the listen port (busy: a warning naming `/healthz` if an Ore answers), and disk space (warn under 1 GiB, fail under 100 MiB); exit status 1 when a required check fails. New flags: `--db`, `--log-format text|json`, `--log-level debug|info|warn|error`, `--backup-to`, `--backup-interval`, `--backup-keep`, `--drain-timeout`.

**Server.** Every response carries `X-Request-ID` (the caller's, else a generated `req_...`); every request is logged with request id, method, path, status, bytes, duration and remote (`/healthz` and `/metrics` at debug level, 5xx at error level) in text or JSON. `GET /metrics` serves Prometheus text format: `ore_build_info`, `ore_uptime_seconds`, `ore_http_requests_total{method,code}`, `ore_http_request_duration_seconds` (summary), `ore_http_requests_in_flight`, and from the ledger at scrape time `ore_pipeline_runs_total{status}`, `ore_deployments_total{status}`, `ore_agent_runs_total{status}`, `ore_ledger_events_total`, `ore_db_open_connections`. On SIGINT/SIGTERM the server stops accepting requests, waits up to `--drain-timeout` (30s) for running pipelines and agent runs to finish, then marks the rest `interrupted` on the ledger (`io.ore.pipeline.run.finished` with status interrupted; agent runs with error "server shutdown"), stops the background workers and closes the database. On start it marks runs a crashed process left `running` as interrupted ("server restarted").

**Packaging.** `VERSION` (0.1.0). `scripts/release.sh` builds static binaries for linux/amd64, linux/arm64, darwin/arm64, darwin/amd64 with the version stamped (`-X main.version`), `SHA256SUMS`, `CHANGELOG.md` from the git log since the last tag, and copies `VERSION` and `install.sh` into `dist/`; `--only host` builds one target. `deploy/install.sh` (`curl -fsSL .../install.sh | sh`) picks the OS and architecture, downloads the archive and `SHA256SUMS`, verifies the checksum, installs to `/usr/local/bin` when writable or `~/.local/bin` otherwise, checks the install directory before downloading and never runs sudo; `ORE_INSTALL_URL` may be a `file://` directory for air-gapped installs. `deploy/Dockerfile` is multi-arch (cross-compile on `$BUILDPLATFORM`, alpine with git, docker CLI and ssh client; built for linux/amd64 and linux/arm64 here, `ore version` inside prints 0.1.0). `deploy/solo/compose.yaml` adds an optional Postgres service (`COMPOSE_PROFILES=postgres`), a backups volume with the scheduled backup variables, and the Litestream profile. `deploy/systemd/ore.service` runs `ore doctor` before `ore serve`, with `TimeoutStopSec=90` to cover the drain. `deploy/RELEASING.md` is the process; nothing is tagged or pushed by scripts.

## Running on Postgres

```bash
docker run -d --name ore-pg -e POSTGRES_USER=ore -e POSTGRES_PASSWORD=ore -e POSTGRES_DB=ore -p 5432:5432 postgres:16-alpine
export ORE_DB_URL='postgres://ore:ore@localhost:5432/ore?sslmode=disable'
ore doctor && ore migrate apply && ore serve
```

Or `COMPOSE_PROFILES=postgres ORE_DB_URL=postgres://ore:ore@postgres:5432/ore?sslmode=disable docker compose -f deploy/solo/compose.yaml up`. Wrong credentials fail fast with `postgres postgres://ore:REDACTED@...: authentication failed, check the user and password in ORE_DB_URL`. The pool is capped at 16 connections.

## Backup and restore

```bash
ore backup --to /backups/$(date -u +%Y%m%dT%H%M%SZ)            # or --to s3://bucket/ore/nightly
ore restore --from /backups/20261019T034100Z --data /var/lib/ore  # into an empty directory
ore restore --from /backups/20261019T034100Z --data /var/lib/ore --db postgres://...   # SQLite backup into Postgres
```

The backup is taken from one snapshot of the ledger (`VACUUM INTO` and a repeatable-read dump) while the server keeps running; a pipeline running at that moment appears as running in the copy and is marked interrupted when a server starts on the restored data.

## Tests

- `internal/ledger/pg`: placeholder rewriting (literals, quoted identifiers, `--` and `/* */` comments, `ON CONFLICT`, JSON in literals), schema rewriting (identity, BIGINT, BYTEA, literals and comments untouched), URL helpers and redaction.
- `internal/ledger`: SQLite path forms; migrations idempotent and listed; six concurrent in-process migrators on one SQLite file; unique violations recognised on both dialects; tables in foreign-key order; dump/load round trip (text with quotes and `?`, blobs, NULLs, event sequence continues after load, load into a non-empty database refused); `VACUUM INTO`; on Postgres (`ORE_TEST_DB_URL`): wrong credentials give a clear redacted error, the dialect is reported, foreign keys hold.
- `cmd/ore`: metrics, request ids and JSON logs through a real server; graceful shutdown drains a running host-executor pipeline (`sleep 2`) to success; a zero drain timeout marks it interrupted and a restart recovers a stale running run; doctor healthy, docker absent (host fallback), read-only data directory (fail), unreachable database (fail, redacted), busy port (warn), pending migrations (warn), report and exit status; config redaction and flag validation; migrate status/apply/idempotent/unknown; four concurrent `ore migrate apply` processes on one database (SQLite and, through a shared schema, Postgres); backup and restore round trip (two repositories, one empty; token and key; the restored server serves the same files, issues and the identical event sequence, then keeps working); scheduled backups write timestamped directories and prune to `keep`; S3 upload of every file plus the manifest against a fake S3 that recomputes the SigV4 signature; the install script (release for the host, `file://` URL, installed binary prints the version; permission failure before download; tampered checksum refused).
- Whole suite on Postgres: `scripts/test-postgres.sh` (result recorded below).

### Edge cases (named tests)

| Case | Test | Result |
|---|---|---|
| Restore into a non-empty directory | `TestRestoreIntoNonEmptyDirectoryIsRefused` | refused before anything is written; a tampered backup is refused on checksum |
| Backup with an unreadable repository | `TestBackupWithUnreadableRepositoryFailsLoudly` | error names `repository acme/locked ... not readable`; no partial manifest |
| Wrong Postgres credentials | `TestPostgresWrongCredentialsGiveAClearError` (Postgres run), doctor `database` check | "authentication failed, check the user and password in ORE_DB_URL", password redacted |
| Migrations already applied on Postgres | `TestMigrationsAreIdempotentAndListed`, `TestMigrateCommandStatusAndApply` (both run on Postgres through the hook) | second `Migrate`/`apply` changes nothing, `0 pending` |
| Concurrent `ore migrate` | `TestConcurrentMigrateProcesses` (processes), `TestConcurrentMigrateOneWinsOthersFindItDone` (in-process, SQLite) | every migrator exits 0 with `0 pending`; one applies each migration |
| Backup during an active pipeline | `TestBackupDuringAnActivePipelineIsConsistent` | checksums stable, the running run is in the snapshot, the copy restores, the original finishes |
| Install script without write permission | `TestInstallScript` | "not writable by <user> ... this script never runs sudo for you", before any download |
| Doctor when Docker is absent | `TestDoctorHealthyAndUnhealthy` | `warn docker ... start with --executor host`; doctor passes |

## Results

- `scripts/e2e.sh` on 2026-10-19 (macOS arm64, Docker 29.1.2, Go 1.26): format, vet, every package, build, the Docker demo in 38.5 s. Passed.
- `scripts/test-postgres.sh` on 2026-10-19 (postgres:16-alpine): every package with tests passed on Postgres (19 packages), including the four concurrent-migrator processes on a shared schema, the dump/load round trip, the wrong-credentials error and the backup/restore round trip; the container was stopped afterwards. The first run exposed GitHub ids overflowing int4, fixed by mapping INTEGER to BIGINT in the dialect rewrite.
